## 常见问题

**覆盖每个国家与地区吗？** 否。本版有 31 个条目，深度不一；非洲与南美洲不在项目范围，其余市场也未逐国完整展开。

**是否逐一核实每种执业资格或许可？** 否。金融牌照、各地签字权与细分合规未形成完整独立训练包；申请前须对照官方现行规则与雇主说明。

**教学案例算工作经验吗？** 不算。案例与填写示例均为教学模拟，简历中只能如实标注为自主练习或模拟项目，不能写成雇主实习或客户交付。

**还有哪些已知缺口？** 见下方[尚未充分覆盖](#尚未充分覆盖)；本 README 不以新增推断填补这些空白。

## 一轮完整行动

1. **定边界。** 准备毕业时间、当前工作资格、语言和可到岗日期；把已确认、未知与不符合分开写。输出资格核验表。
2. **研究岗位。** 为两个候选子职能收集真实原始 JD；拆出职责、硬门槛、能力与评估。输出岗位研究表与主备方向。
3. **补证据。** 对照 JD 写本人动作、已有材料、缺口和期限。输出能力证据表与行动计划。
4. **做专业练习。** 选择对应案例，先独立作答，再看参考解与评分。输出一套算得清、讲得明的工作样本。
5. **申请与评估。** 用真实经历制作定向中英文材料，练雇主实际采用的案例、行为、展示、测评或群体任务。输出材料版本与复盘。
6. **调整目标。** 保存申请事件和明确反馈，在可比较批次内定位问题；每轮调整一个主要变量。输出下一轮决策。

所有章节中的步骤都给出输入、操作、输出、验收和错误处理。训练时间表是行动建议，不代表固定录用周期。

- 中国内地落户补贴、公职、社保档案与逐项职业准入没有完整核查。回国雇主样本以金融和专业服务为主；其他行业需补充目标企业当季日历。

## 开发与复现

网站是静态 HTML/CSS/JavaScript，正文来自 Markdown，无需后端。已构建版本在 `dist/`，不收集读者简历或身份资料。

```bash
npm install
npm run build
python3 scripts/verify.py
node --check assets/app.js
```

重新排版 PDF 需要 Python 3、`requirements-pdf.txt` 中的依赖及 Noto CJK 字体；先生成 `book.json`：

```bash
python3 -m pip install -r requirements-pdf.txt
python3 scripts/build-pdf.py
python3 scripts/package.py
npm run build
python3 scripts/verify.py
```

Linux 字体路径见构建脚本；其他系统需调整本地字体路径。工作簿构建脚本使用 `@oai/artifact-tool`，该运行时不包含在普通 npm 安装中；读者可直接在 Excel、WPS 或兼容软件中编辑已交付 XLSX，CSV 与 JSON 定义也完整开放。不要为了阅读或填写模板而重建工作簿。

网站统一由 GitHub Pages 发布 `dist/`。本仓库提供自动发布工作流与限定目标仓库的发布脚本；最新部署要求见 [DEPLOYMENT.md](DEPLOYMENT.md)，执行记录见 [PUBLISH.md](PUBLISH.md)。
